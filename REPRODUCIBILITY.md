# Reproducibility Statement

## Objective
The reproducibility objective is to make the SSAC27 evaluation transparent enough that an independent researcher can understand the experimental population, outcome definitions, aggregation rules, audit decisions and statistical calculations, and can reproduce every released result from legally releasable artifacts.

This is distinct from reproducing the private operational FST.ai implementation.

## Current abstract-stage package
The repository now provides:
1. the research question and FST/FST 2.0-only scope;
2. source-data status and rights constraints;
3. a public, de-identified candidate-level annotation table;
4. a canonical exact-deduplicated version plus explicit audit log;
5. machine-readable audit summaries and an audit-reproduction script;
6. metric definitions and a statistical analysis plan;
7. deterministic ground-truth/model event-matching code;
8. structural validation and model-performance evaluation scripts;
9. a frozen-model export specification and model-manifest template;
10. a populated claim/evidence ledger separating verified results from unreconciled prior-public claims;
11. a final evidence-grounded abstract candidate, claim map, copy/paste submission text, and rewritten current-evidence manuscript.

## Current reproducible result
From the released candidate annotation data, an independent user can reproduce:
- raw and canonical record counts;
- TP/FP candidate-validation counts;
- the canonical candidate-confirmation proportion;
- category distributions;
- exact duplicate detection;
- the highly repeated joint annotation patterns.

These are annotation-population results. They are not presented as full event-level FST recall/F1 or as model-uncertainty validation.

## Full event-level benchmark
Before manuscript-ready event-level model performance is reported, the package requires two independently frozen layers:
- `ground_truth_events.csv`: an independently enumerated reference-event population including events missed by the model;
- `fst_ssac_predictions.csv`: all predictions generated by the frozen FST/FST 2.0 configuration without access to reference labels.

`evaluation/match_events.py` then derives TP, FP and FN under a declared temporal/class rule. `evaluation/evaluate_predictions.py` computes metrics, clustered intervals, contextual strata and risk-coverage output when genuine numerical model uncertainty is available.

## Claim-level provenance
For every reported quantitative result the evidence ledger records, where applicable:
- source experiment/deployment;
- evaluation unit;
- population and denominator;
- inclusion/exclusion rules;
- reference/ground-truth procedure;
- model/configuration version;
- point estimate and uncertainty interval;
- aggregation method;
- clustering unit;
- release status.

Prior-public FST/FST 2.0 numbers that have not yet been reconstructed from source observations remain explicitly quarantined rather than presented as newly verified SSAC results.

## Reproducibility boundary
Reproduction of released evaluation calculations does not by itself require publication of production source code, trained production weights, private deployment configuration, credentials or protected implementation know-how. Frozen model outputs and sufficient model/configuration provenance should be released where rights and confidentiality permit.

## No synthetic substitution
If an underlying observation cannot legally be released, this repository will not substitute synthetic observations and present them as original evidence. Any simulated data used solely for software tests are explicitly labelled and are not evidentiary support for empirical claims.

## Automated checks
A GitHub Actions workflow, `reproducibility-smoke-test`, now runs on changes to the evaluation package. It installs the declared Python dependencies, compiles the evaluation scripts, and executes `evaluation/tests/smoke_test.py`.

CI execution has been observed and verified as successful on the public repository. In particular, workflow run 21 completed successfully for commit `4679fcb1c092dfd7c75bc0aca7eddb6cd48346a4` after correction of the package-audit utility. This establishes that the public evaluation code is not only documented but passes the repository's current automated smoke-test gate.

The CI check is intentionally a structural/reproducibility test; it does not substitute for the still-pending empirical frozen-model benchmark, independent ground-truth event census, or raw-video rights review.
