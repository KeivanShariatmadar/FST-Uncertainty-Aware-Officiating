# FST / SSAC Evidence Audit Protocol

## Scope
This protocol applies only to the FST.ai and FST.ai 2.0 officiating research line. APEX, Digital TA, WT-SCIP/SCIP, SILs, and other projects are explicitly out of scope.

## Governing principle
No quantitative result is promoted to the SSAC manuscript unless its numerator, denominator, evaluation unit, provenance, ground-truth procedure, and inclusion/exclusion rules can be reconstructed.

## Evidence roles
Every analytical field must be assigned to one provenance role:
1. Ground truth: independently adjudicated reference event/decision.
2. Model output: generated by the frozen FST/FST 2.0 implementation without access to reference labels.
3. Independent contextual annotation: visibility/occlusion, contact quality, action type, difficulty, or human ambiguity recorded independently of model correctness where possible.
4. Derived variable: TP/FP/FN status, error, coverage, latency reduction, or another quantity computed from preceding layers.

Human annotation confidence is not model epistemic uncertainty. A human `uncertain` label is not a numerical FST uncertainty output.

## Immutable raw layer
Original videos, source annotations, and deployment records remain unchanged. Corrections are represented through an audit layer rather than destructive editing.

## Identity and duplicate audit
For every candidate evaluation unit record: source match/bout identifier; clip/event identifier; source split/location; duplicate status and reason; canonical evaluation identifier; inclusion/exclusion status and reason.

Known working-annotation issues, including repeated match/clip records and inconsistent match-number bookkeeping, must be resolved explicitly.

## Ground-truth requirement
The primary event-level benchmark should enumerate relevant true events independently of FST detections. This is necessary to observe false negatives and therefore estimate recall and F1.

If a subset consists only of FST-proposed candidate clips that were subsequently human-validated, it is a candidate-detection validation sample. It may support precision under its declared sampling design, but does not by itself support recall or F1.

## Frozen-model inference
Before evaluation record: implementation/version or commit; model/weights identifier and checksum where releasable; inference thresholds; preprocessing; temporal/event aggregation; software/hardware environment; random seeds where applicable; and exact numerical confidence/evidence/uncertainty outputs available from FST.

Reference labels must not be used to tune the frozen final-test configuration.

## Event matching
Model events and reference events are matched using a declared deterministic protocol. The manuscript must state temporal tolerance/window, class compatibility, treatment of multiple predictions for one event, unmatched predictions, and unmatched references.

After matching: matched qualifying model/reference event = TP; unmatched model event = FP; unmatched reference event = FN. TN is reported only if a defensible negative evaluation unit is explicitly defined.

## Primary metrics
Where supported report precision = TP/(TP+FP), recall = TP/(TP+FN), F1, declared class-specific/macro/micro aggregates, and contingency counts alongside rates. Do not report recall or F1 from a dataset that does not enumerate FN.

## Dependence and uncertainty intervals
Events from the same bout are not assumed IID. Principal uncertainty intervals should use bout/match-level cluster resampling where feasible. Athlete-level dependence should be examined where stable athlete identifiers exist.

## Contextual robustness
Where independently annotated, stratify performance by turning/non-turning action, visibility/occlusion, contact quality, difficulty, and human reference confidence/ambiguity. These variables characterize evidence conditions; they are not substitutes for FST uncertainty.

## FST 2.0 uncertainty / selective prediction
Use the actual numerical model evidence/uncertainty output where available. For uncertainty U(x) and threshold tau, coverage C(tau) is the proportion retained for AI-supported decision and selective risk R(tau) is the declared error rate among retained cases. Report risk-coverage behavior and characterize deferred cases. Headline thresholds must not be selected on the final test population.

## Latency
Review-time claims require a precisely defined baseline and assisted workflow, identical start/end events, sample size, aggregation level, and distributional reporting. Prefer median, IQR, and empirical distributions in addition to relative reduction.

## Human trust/acceptance
No trust/acceptance percentage is used without respondent population, n, question wording/operational definition, response scale, aggregation rule, and study context.

## Sensitivity analyses
At minimum consider raw versus deduplicated population, alternative defensible event-matching tolerances, inclusion/exclusion of human-ambiguous references, contextual strata, and clustered versus naive uncertainty intervals.

## Release gate
A result is manuscript-ready only if classified Verified in the evidence ledger and regenerable from a traceable evidence chain. Unsupported or partially supported claims remain labelled accordingly and are not converted into empirical findings.
